# Workload Identity Federation Deploy Pipeline

## What's set up
- WIF pool: `github-actions`, provider: `github`, locked to `FlubaDesigns/litigant-ai`
- Service account: `litigant-ai@appspot.gserviceaccount.com` (App Engine default SA)
- Project number: `781960492360`
- Workflow file: `.github/workflows/deploy-cloudrun.yml`
- Every push to `main` → deploys Cloud Run env vars + builds + deploys Firebase Hosting

## GitHub Actions secrets required
All pushed from Replit env via tweetsodium:
- `WIF_PROVIDER` = `projects/781960492360/locations/global/workloadIdentityPools/github-actions/providers/github`
- `WIF_SERVICE_ACCOUNT` = `litigant-ai@appspot.gserviceaccount.com`
- `FIREBASE_SERVICE_ACCOUNT_JSON` (mapped from `FIREBASE_SERVICE_ACCOUNT` Replit env)
- `SESSION_SECRET`, `VITE_FIREBASE_*`, `VITE_API_URL`
- All AI/payment keys already in GitHub from before

```bash
// ... encrypt with KEY_ID=3380204578043523366, KEY_B64=E4QXCOfax3QtSrjw/j4vJwFyK5wNsWU9acW30mM5GzU=

```

## Quirks fixed during setup
- WIF secrets added to Replit secrets first (wrong) — had to re-push via GitHub API
- pnpm version mismatch: workflow must use `version: 10` (lockfile was generated by v10.26.1)
- `vite.config.ts` threw on missing `PORT` during CI builds — fixed: skip check when `NODE_ENV=production`
- Provenance check (`/api/version`) is `continue-on-error: true` — SHA will read "unknown" until 
  the first deploy that includes the new `/version` endpoint lands on Cloud Run

**Why:** No SA JSON keys to rotate/leak. Google auto-revokes keys detected in session output — this happened twice before WIF was set up.
